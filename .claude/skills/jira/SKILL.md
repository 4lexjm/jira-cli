# Jira CLI (`jira`)

Use `jira` for Jira Cloud and Jira Data Center operations. Prefer structured
`--json`, `--yaml`, `--jq`, or `--template` output for automation.

## Start with the requested operation

Run `jira --version` only when installation or compatibility is uncertain. Run
`jira auth status` when the command needs authentication or the active instance
and context are unknown. Do not make setup a prerequisite for an already
configured read-only request.

Cloud and Data Center have different feature sets. Determine the deployment
from the active context or ask when it cannot be inferred. Do not suggest a
Cloud-only command for Data Center, or the reverse.

Read [setup and common workflows](rules/guide.md) when installing, authenticating,
creating a context, or learning the main command patterns. For config-free CI or
containers, read [headless authentication](rules/headless.md).

## Mutation and credential boundaries

- Listing, viewing, searching, and status checks are read-only. Create, edit,
  transition, assign, comment, delete, or permission changes modify Jira;
  perform them only when the user requested that change.
- Never place tokens, API tokens, or passwords in commands that could enter
  logs or committed files. Use the CLI's supported credential flow or
  environment variables described in the auth references.
- Before a transition, deletion, or other consequential write, inspect the
  exact issue, project, and current state. Report the resulting URL or key.
